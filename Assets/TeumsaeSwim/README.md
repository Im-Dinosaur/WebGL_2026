# 숨바꼬기

작은 물고기가 바위와 수풀, 좁은 틈, 그물을 이용해 포식자를 피하고 출구에 도달하는 2D 세로형 WebGL 게임입니다.

- Unity: **6000.3.23f1**, URP 2D, Input System, uGUI
- 전용 씬: `Assets/TeumsaeSwim/Scenes/TeumsaeSwim.unity`
- 웹 빌드: `docs/teumsae-swim/`
- 게시 주소: https://im-dinosaur.github.io/WebGL_2026/teumsae-swim/
- 기존 실습 씬, 기존 Pages 루트의 게임은 별도로 유지합니다.

## 실행과 조작

Unity에서 전용 씬을 열고 Play를 누릅니다. 씬과 프리팹의 참조는 연결되어 있습니다. Game View를 480 × 854 또는 9:16에 가까운 세로 화면으로 설정하면 웹 화면을 확인하기 쉽습니다.

| 행동 | 모바일 | PC |
| --- | --- | --- |
| 헤엄 | 왼쪽 스틱 | WASD / 방향키 |
| 틈 통과 | 오른쪽 ‘꾹’을 누르며 이동 | Space + 이동 |
| 그물 작업 | 그물 근처에서 이동하며 ‘꾹’ 유지 | 이동 + Space |
| 미끼 | 미끼 버튼 | E |
| 진주 획득 | 진주에 가까이 닿으면 자동 획득 | 동일 |
| 일시정지 | 상단 Ⅱ | Escape |

시간 제한은 없습니다. 전체 물길을 매번 무작위로 생성하며, 플레이 시간은 숙련도와 경로 및 난이도에 따라 달라집니다. 카메라가 플레이어를 가로·세로로 부드럽게 따라가고 미로 경계에서 멈춥니다. 정보와 조작 버튼은 화면에 고정됩니다.

## 주요 규칙

- 연습/기본/도전은 각각 25×25 / 31×31 / 37×37칸이며 포식자는 2/4/6마리입니다. 무작위 깊이 우선 탐색으로 전체 통로를 연결한 뒤 일부 벽을 열어 갈림길, 막다른 길, 순환 우회로를 만듭니다. 동일한 구간 템플릿을 반복하지 않습니다.
- 시작점과 출구는 위치와 방향이 매번 달라집니다. 실제 통로 거리와 직선 거리가 충분히 먼 곳을 선택하고, 안전방과 장애물을 배치한 뒤 모든 물길의 연결을 다시 검사합니다. ‘같은 미로 다시 도전’은 시드를 유지해 지형과 배치를 재현합니다.
- 시작과 도착 주변은 각각 3×3칸의 민트색 안전구역입니다. 그물·틈·포식자를 배치하지 않으며 포식자의 길찾기와 몸체 진입을 모두 막습니다. 플레이어 중심이 안전구역 안에 있으면 발견·포획되지 않습니다. 안전구역에서도 미끼를 발사할 수 있고 경계를 넘어 날아갑니다.
- 틈과 그물은 통과 방향이 명확한 직선 통로에 배치하고, 풀숲과 포식자는 실제 통로에 맞춰 분산 배치합니다. 진행 막대는 높이가 아닌 출구까지 남은 통로 거리를 기준으로 하므로 돌아가면 줄어들 수 있습니다.
- 각 미로에는 선택 목표인 빛나는 진주가 하나 있습니다. 최단 탈출 경로에서 벗어난 도달 가능한 물길에 배치하며, 안전구역·장애물·포식자 바로 옆은 피합니다. 기본 설정에서는 시작·출구에서 각각 6칸 이상 떨어지고 경유 시 6칸 이상 더 이동하는 후보를 우선합니다. 작은 사용자 설정 미로에서는 연결된 짧은 분기를 사용할 수 있습니다.
- 진주에 몸체가 닿으면 한 번만 자동 획득하며 벽 너머에서는 주울 수 없습니다. 지도에서 진주가 사라지고 상단에 ‘진주 운반 중’이 표시됩니다. 미끼 사용과 일시정지 중에도 보유 상태를 유지합니다.
- 진주를 가진 채 탈출하면 결과 화면에 ‘진주 운반 성공’, 운반 중 잡히면 ‘진주 운반 실패’가 표시됩니다. 진주 없이도 탈출할 수 있습니다. 같은 미로 재도전은 같은 위치에 진주를 복구하고 보유·운반 결과를 초기화합니다. 새 미로에서는 새 시드로 배치합니다.
- 이번 단계는 아이템 획득과 운반 결과까지 구현합니다. 별 3개 평가와 제한시간 보너스는 이후에 연결하며, 현재는 제한시간이 없습니다.
- 바위는 이동과 시야를 막습니다. 수풀 안에 몸 전체가 들어가면 시야에서 숨고 포식자와 접촉해도 잡히지 않습니다. 몸이 수풀 밖으로 나오면 보호가 해제됩니다.
- 좁은 틈은 누른 상태에서만 이동합니다. 안에서 놓으면 작은 자세로 멈춥니다. 포식자는 통과하지 못하며 틈 자체는 투명한 통로입니다.
- 그물은 이동을 막지만 시야는 통과합니다. 가까이서 이동과 ‘꾹’을 함께 누르면 누적 2초 후 열립니다. 범위를 벗어나거나 버튼을 놓으면 중단하고 진행도는 유지됩니다. 그물 작업 중에는 몸을 줄이지 않으며, 일반 물길에서 ‘꾹’만 누른다고 느려지지 않습니다.
- 미끼는 2개이며 발사에 성공할 때만 소모됩니다. 바라보는 방향으로 6.6유닛까지 날아가며, 벽·닫힌 그물·포식자가 통과하지 못하는 틈에 닿으면 한 번 반사하여 1.1유닛 이동 후 정지합니다. 정지 후 8초 동안 유지됩니다.
- 미끼가 정지하면 8.8유닛 반경 안에서 접근할 경로가 있는 포식자가 ‘?’를 띄우고 이동합니다. 벽 너머라도 돌아갈 길이 있으면 반응하며, 도착해 먹거나 미끼가 사라지면 순찰 위치로 돌아갑니다. 플레이어를 직접 발견하면 발견·추격을 우선합니다.
- 포식자는 종류별 발견 대기 시간이 쌓이면 추격합니다. 시야를 놓치면 주변 미끼에 반응하거나 발견 직전 순찰 위치로 복귀합니다. 재발견은 해당 종류의 대기 시간을 처음부터 다시 쌓습니다. 모든 종류에 바위의 시야 차단, 수풀·안전구역 보호, 미끼 유인을 동일하게 적용합니다.
- 같은 프레임에 접촉과 출구 도달이 발생하면 잡힌 결과가 우선합니다.
- 창 전환 시 자동 정지하며 다시 누르기 전까지 진행하지 않습니다. 최고 기록과 음소거는 브라우저의 로컬 PlayerPrefs에 저장됩니다.

## 구조

### 포식자 4종

| 종류 | 탐지 거리 | 발견 대기 | 순찰 / 추격 / 유인 속도 배율 | 외형 |
| --- | --- | --- | --- | --- |
| 보라 기본형 | 3.5 | 0.9초 | 1 / 1 / 1 | 둥근 보라 몸, 코랄 지느러미 |
| 파랑 정찰형 | 5.6 | 1.1초 | 0.8 / 0.8 / 0.8 | 큰 눈과 통통한 파란 몸 |
| 빨강 예민형 | 2.8 | 0.45초 | 1 / 1 / 1 | 붉은 몸과 높은 등지느러미 |
| 분홍 추격형 | 3.5 | 1.2초 | 1 / 1.3 / 1 | 길쭉한 몸, 큰 갈라진 꼬리 |

거리는 월드 유닛이며 시야각은 기존 86도를 유지합니다. 이동 배율은 프리팹의 기본 순찰 1.22 / 추격 3.7 / 유인 2.1에 적용하고, 난이도 배율(연습 0.8 / 기본 1 / 도전 1.06)은 별도로 한 번 적용합니다. 충돌 반경은 모든 종류가 기존 0.43을 유지합니다.

연습은 기본형 한 마리와 무작위 특화형 한 마리, 기본은 네 종류 한 마리씩, 도전은 네 종류에 중복 없는 두 종류를 추가합니다. 같은 미로 재도전은 종류와 배치 순서도 재현합니다. 색뿐 아니라 몸통·눈·꼬리 모양과 이름 표시로 구분하며, 헤엄 애니메이션은 일시정지 중 멈춥니다. 조작 안내에서 각 종류의 특징을 볼 수 있습니다.

종류별 조정값과 그림은 `Art/PredatorTypes/*.asset`의 Inspector에서 편집합니다. `PredatorRosterComponent`가 조합을 만들고 `SwimGame → Predator`가 같은 설정을 AI·이동·표시 컴포넌트에 전달합니다. `PredatorTypeProfile`은 설정 자원이며 AI는 탐지, Movement는 행동별 속도, Visual은 그림과 시야 표시만 담당합니다. 씬의 Roster와 네 설정, 투명 스프라이트 참조는 연결되어 있습니다. `Teumsae Swim/6. Connect predator types` 메뉴는 씬 전체를 다시 만들지 않고 연결하며 기존 종류별 능력치 조정값을 보존합니다.

외부 호출은 `SwimGame`, `Player`, `Predator`, `Maze` 진입점을 통합니다. 각 진입점은 담당 Component를 연결하고 순서대로 호출합니다.

| 진입점 / 구성 요소 | 책임 |
| --- | --- |
| SwimGame / GameSessionComponent | 시스템 진행 순서, 게임 단계, 시간, 승패, 기록 |
| Player / Input, Movement, Interaction, Visual Component | 입력, 헤엄과 틈 통과, 그물과 미끼, 물고기 표시 |
| Predator / AI, Movement, Visual Component | 발견·추격·복귀 판단, 길찾기, 시야 표시 |
| PredatorRosterComponent / PredatorTypeProfile | 재현 가능한 종류 조합, 종류별 능력치와 스프라이트 설정 |
| Maze / Generation, Terrain, Bait, Item Component | 전체 무작위 미로 생성과 연결 검증, 안전구역·충돌·시야·지형, 미끼 비행과 수명, 진주 배치·표시·획득 |
| CameraFollowComponent | 고정 배율의 플레이어 추적과 맵 경계 제한 |
| GameUIComponent / TouchControlComponent | 고정 UI, 스틱과 누르기 입력 |
| GameAudioComponent / SwimArt | 직접 합성한 효과음, 코드로 만든 도형, 한국어 글꼴 |

Inspector에서 각 Component의 이동 속도, 시야 거리, 발견 시간 등을 조절할 수 있습니다. 프리팹의 포식자 설정은 새 판을 시작할 때 적용됩니다.

`MazeBaitComponent`의 `launchSpeed`, `launchDistance`, `bounceDistance`, `attractDistance`, `baitDuration`으로 미끼를 조절합니다. `MazeGenerationComponent`의 `practiceSize`, `normalSize`, `challengeSize`로 난이도별 미로 크기를, `loopRatio`로 추가 우회로 비율을 조절합니다. 짝수 크기는 다음 홀수로 맞춥니다. 포식자 수 설정도 같은 구성 요소에 있습니다. 기존 씬의 참조는 연결되어 있어 바로 Play할 수 있습니다. `Teumsae Swim/4. Apply feedback update` 메뉴는 씬 전체를 재생성하지 않고 미끼 연결과 기본 난이도·발견 시간 설정을 적용합니다.

진주는 `Player → PlayerInteractionComponent → Maze → MazeItemComponent` 순서로 획득합니다. 보유 상태는 `Player.hasCargo`로 조회하며, `SwimGame`이 탈출 판정에 함께 전달합니다. `GameSessionComponent.cargoDelivered`는 성공적으로 운반한 결과만 유지하고 `SwimGame.cargoDelivered`를 통해 UI와 향후 별 평가에 제공합니다.

`Maze` 오브젝트의 `MazeItemComponent`에서 `pickupRadius`(진주 획득 반경), `minimumDetour`(선호하는 우회 칸 수), `endpointClearance`(시작·출구와의 통로 간격), `predatorClearance`(포식자 생성 위치와의 간격)를 조절합니다. 기본값은 각각 0.3 / 6 / 6 / 2이며, `art`는 공용 `SwimArt` 자원에 연결합니다. 기존 씬에는 연결이 완료되어 있고, 다른 복사본에는 `Teumsae Swim/5. Connect pearl item` 메뉴로 진주 구성 요소만 연결할 수 있습니다.

## 검증과 빌드

Unity 메뉴 `Teumsae Swim`에 씬 생성, 규칙 검사, WebGL 빌드가 있습니다. **씬 생성 메뉴는 전용 씬과 포식자 프리팹을 재조립하므로 수동 편집 후에는 필요한 경우에만 사용하세요.** 규칙 검사는 임시 실행 상태를 만든 뒤 저장하지 않고 원래 씬을 다시 엽니다.

검사는 600개의 랜덤 미로에서 지형과 시작·출구 위치의 다양성, 시드 재현, 모든 물길의 연결, 안전구역과 출구 거리 및 진행률을 확인합니다. 실제 이동과 게임 루프에서는 양쪽 안전구역의 진입·발견·접촉 차단, 안전구역에서의 미끼 발사를 확인합니다. 기존 그물 동시 조작, 미끼 반사·유인, 풀숲 보호, 0.9초 발견, 일시정지와 결과 규칙도 검사합니다. 세 난이도의 총 12개 미로에서는 실제 몸체와 누르기 조작으로 출구까지 통과합니다. 보고서는 Git에서 제외되는 `Logs/TeumsaeSwim/verification.txt`에 저장됩니다.

아이템 검사는 600개 미로의 진주 배치·우회·도달 가능성과 같은 시드의 재현을 확인합니다. 실제 플레이어 입력으로 시작→진주→출구를 이동하며 자동 획득과 운반 성공을 검사하고, 벽 너머 획득 방지·중복 획득·일시정지·미끼 사용·운반 중 사망·아이템 없는 탈출·재도전 초기화·HUD와 결과 문구도 확인합니다. 검사 중 사용자의 기존 최고 기록은 보존합니다.

종류별 검사는 600개 조합의 다양성·재현·중복 제한, 네 스프라이트 참조, 실제 거리 판정과 발견 시간 경계, 바위 차단, 세 난이도에서 순찰·추격·유인의 실제 이동량, 초기화 시 배율 중복 방지, 미끼에 도착해 먹기, 좌우 방향과 일시정지, 재도전 및 모든 종류의 풀숲·안전구역 접촉 보호를 확인합니다.

빌드는 전용 씬만 포함하며 `docs/teumsae-swim`에 출력합니다. 기존 EditorBuildSettings의 실습 씬 목록을 바꾸지 않고 일시적으로 바꾼 PlayerSettings는 복구합니다. GitHub Pages의 정적 호스팅을 위해 Gzip과 Decompression Fallback을 사용합니다. 웹 템플릿은 모바일 세로 비율, 로딩 진행도, 오류 후 재시도 화면을 제공합니다.

WebGL 파일은 파일 탐색기에서 직접 열지 말고 HTTP 서버나 게시 주소로 접속합니다. `main`의 `/docs`를 사용하는 기존 GitHub Pages 설정에서는 해당 폴더의 커밋이 게시됩니다.

수정 작업 중에는 로컬 소스 반영과 검증까지만 진행합니다. 사용자가 최종 배포를 요청한 뒤 WebGL 빌드와 GitHub Pages 게시를 함께 진행합니다. 그 전까지 공개 주소와 기존 웹 빌드에는 마지막으로 게시한 버전이 남습니다.

## 자원

포식자 네 종류는 승인한 시안을 바탕으로 내장 이미지 생성 도구로 만든 투명 그림 `Art/PredatorAtlas.png`를 사용합니다.
